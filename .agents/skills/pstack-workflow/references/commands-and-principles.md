# pstack 快捷口令与工程原则速查表

用户在对话中提到以下任一口令时，Antigravity 应自动加载 `pstack-workflow` 并按对应模式执行。

---

## 一、常用快捷口令映射

| 用户口令示例 | 含义 | 执行模式 |
| :--- | :--- | :--- |
| `poteto-mode <目标>` / `用 pstack 做 <目标>` | 总入口路由 | 自动识别任务类型 → 选 Playbook → 拆清单 → 强制真实运行验证 |
| `how <某功能/模块>` | 追踪真实运行链路 | 只读调研，给带文件行号的执行流说明，不改代码 |
| `why <某段逻辑/设计>` | 追溯历史背景 | 查 git 历史与提交上下文，还原决策动机，不改代码 |
| `architect <需求>` | 编码前定边界 | 先输出数据结构、接口契约、影响面与分步验证计划 |
| `interrogate` / `审查 diff` | 对抗式 Code Review | 针对当前变更做边界、并发、契约与测试有效性拷问 |
| `deslop` / `去水` | 清理 AI 痕迹 | 删废话注释、删多余抽象、压缩膨胀代码，保持行为不变 |
| `arena <方案分叉>` | 多方案并行比武 | 独立子代理实现候选方案，实测对比后择优落地 |
| `swarm <批量切片>` | 多 Agent 并行分片 | 独立模块并行开发，主线程统一合并与回归验证 |

## 二、七大原则速查（触发红灯自检）

| 原则 | 一句话判定标准 | 典型违规红灯 |
| :--- | :--- | :--- |
| **Evidence First** | 没读过真实代码和运行证据，不许下结论 | “看文件名这里应该是…”、“我猜可能是…” |
| **Fix Root Causes** | 治病去根，不贴创可贴 | 加 `setTimeout`/`sleep` 绕过竞态、空 `catch` 吞异常 |
| **Laziness Protocol** | 解决问题的最小正确改动 | 改 1 个 Bug 顺手重写了半个文件、提前造通用框架 |
| **Model the Domain First** | 数据结构和状态机先行 | 边写边塞散落布尔标志位（`isA && !isB && hasC`） |
| **Prove It Works** | 没亲眼看到运行结果不算完 | “已修改完毕，类型检查通过，理论上应该没问题” |
| **Test Behavior** | 测输入输出与持久化，不绑定内部细节 | 测试里全是 mock 私有方法调用次数 |
| **Encode in Code** | 踩过两次的坑变成机器检查 | 只在文档里加一行“请务必注意不要 xxx” |

## 三、与工作区现有规范的配合

- **与 `karpathy-guidelines` 的关系**：两者高度一致（简单优先、外科手术式改动、目标驱动验证）；`pstack-workflow` 在此基础上补全了 **Playbook 任务路由、只读 `how`/`why`、对抗式 `interrogate`/`deslop`、规则进代码护栏，以及多 Agent 并行协议**。
- **与 `AGENTS.md` 中 `Superpowers` 的关系**：简单问答与单步命令两者均不加载；当用户明确指定 `pstack` / `poteto` / `lauren` 时优先按 `pstack-workflow` 执行；当用户明确指定 `TDD` / `superpowers` 时按 `Superpowers` 执行。
